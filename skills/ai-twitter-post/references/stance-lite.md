# 叙事与事实（推特帖）

从长文 skill `wechat-author-ai` 压成短帖版。管「怎么讲清、怎么不编」；标题提纲与字数见上级 `SKILL.md`。

## 校准三条

1. **中间带**：别为「冲」堆惊叹；上限不是目标。
2. **3～5 个要点**：一篇只抓这些，其余略写或不写。
3. **留一处平淡**：不必每句判断或金句。

## 事实分栏（成文前过一遍）

| 栏 | 进正文？ | 写法 |
| --- | --- | --- |
| 已核对事实 | 是 | 原文白纸黑字：数字、产品名、门槛、接口 |
| 对方自己的说法 | 是，但标清 | 「最强/唯一/首次」→「他们自己的说法是」，不当测量 |
| 对照 | 慎用 | 两边都有出处才比；缺的一边「这里没有公开数字」 |
| 我的判断 | 至多一句 | 有代价：解决了 A、还没碰到 B；或还缺哪项证据 |
| 无法确认 | **否** | 抓不到、对不上、凭印象 → 整句删 |

## 怎么讲

- **开场**只写原文里那一件具体的事（一个动作 / 数字 / 改动）。拿掉产品名还能套上一篇 → 重写。
- **禁开场**：「大家以为…其实…」「很多人觉得 AI…」。
- 核对过的事实，**下一句立刻人话**（实际改变了什么）。
- 术语可留，下一句必须大白话；一句不堆多个未解释专名。
- 不堆「炸了 / 杀疯了 / 史诗级 / 划时代」；不编「我测过」（用户没提供就不写）。
- 「在我看来」整帖最多一句；结尾不落「提醒我们 / 值得关注 / 凸显重要性」。

## 读后观感

正文是个人转述，不是「对照提纲写摘要」。

- 幕后用 Title/H2 定主线；正文里不要写「标题把…」「按原文小节」「这篇讲了五件事」。
- 可以用「我看下来」「这场更像…」；不要用「原文目录如下」。

## 删改测试

- **删除**：删掉不伤主线 → 删。
- **对调**：两段对调后仍通 → 多半是条目堆，合并或重写因果。

## 语气样本（只学口气，不套开场）

事实 → 人话：

> 文档写明本机接口在 127.0.0.1。说白了，分类跑在你自己电脑上，内容不用先上传。

说法 ≠ 测量：

> 简介里强调「无账单」。这是产品条件，不是评测结论。

判断有代价：

> 在我看来，值得先试的是把问题和门槛在私有数据上调顺；本机权重和云端不是同一份，门槛不能直接照搬。
