# 根据链接或 brief 写 AI 推特帖

主题偏 AI/科技。有原文时：**标题结构定主线 → 事实分栏 → 口语写成读后观感**。叙事细节见 [`references/stance-lite.md`](references/stance-lite.md)。

## 何时用

- 要写成 X/推特**帖**、短线程，或「发条推」
- 不要用于：公众号长文、推特 Articles 长文、小红书（各有专用 skill）

## 默认（可当场改口）

| 项 | 默认 |
| --- | --- |
| 形态 | 一条发完；装不下或用户点名再拆短线程 |
| 语气 | 个人读后观感：像跟同行聊刚看完的东西，不是通稿摘要 |
| 字数 | **X Premium**：不以 280 硬顶；写清、读顺优先。说「短帖/280/免费版」再压 |
| 软参考 | 常见约 600～1500 字；写清即可更短。仍说不完 → 线程或问是否拆 |
| 链接 | 有原文则文末带原链 |
| hashtag / emoji | 默认不加 |
| 份数 | **默认交 2 个变体**（全景 / 落地），事实锚点同一套，开场/侧重不同，方便选一篇发；用户只要 1 版再说 |

## 硬原则（四条）

1. **对题**：主线来自 Title + 开篇 + 主要 H2/H3，不另造「更抓人」的主题。
2. **真**：无法确认不写；营销说法标成说法，不当测量（见 stance-lite 分栏）。
3. **顺**：每句能复述；事实后跟人话；不为凑短掐掉关键限制。
4. **够**：宁肯稍长写全要点，也不为 280 牺牲主线。

## 读后观感（禁原文痕迹）

正文像**自己读完后的转述 + 观感**，不要露出「我在对照稿子写摘要」的痕迹。

**禁止写进正文：**

- 「标题把…拎成主打」「正文其实是…」「按原文小节」「这篇在讲什么」「原文写了五件事」
- 「量子位/某媒体文章说」当开场壳（文末链即可；供稿转载可在边界段点一句）
- 「第一、第二」仅当自己在数要点时可用，不要写成目录复述口吻

提纲、分栏只在**幕后**用；读者只看到你在讲事。

## 通顺门禁

1. 每句：谁、做了什么、结果？说不清就改。
2. 术语先中文后英文；一句不堆 ≥3 个未解释英文标识。
3. 一段一个意思；列表每条是完整短句。
4. 过 stance-lite 的删除测试、对调测试。

## 步骤

### 模式 A · 有链接

1. **Jina 拉原文**（[`../_shared/references/fetch-jina.md`](../_shared/references/fetch-jina.md)）。失败 → 停，说明缺什么，不凭记忆写。
2. **抽提纲**：Title、主要 H2/H3、开篇第一段 → 主题骨架（不写进正文）。
3. **事实分栏**：已核对 / 对方说法 / 对照（可选）/ 判断（≤1）/ 无法确认（不进正文）。见 stance-lite。
4. **定主线**：一句话，须被骨架支撑。
5. **写 2 个变体**（见下）→ 各过 voice-profile + unslop 短帖档 → 通顺门禁 → 交付。

### 模式 B · 无链接

1. **主题未锁**：出 3～5 张卡片后可等选。每张：`拟题 | 核对对象（哪类材料）| 判断方向（还缺什么 / A 有 B 无）`。卡片不写未核对数字。
2. **主题已锁**：无权威出处则停笔说明缺什么，不硬写新闻事实。
3. 成文标「基于 brief，非转载」；默认仍交 2 变体（若材料够）；过通顺门禁。

### 两变体（同一锚点，不同切入）

共用同一事实分栏与主线；**不要**为凑差异改数字或加戏。字数仍按 Premium 软参考，**不**为变体压回 280。**不写第三版「判断」变体**（判断收在各版末尾那一句即可）。

| 变体 | 切入 | 读者带走什么 |
| --- | --- | --- |
| **A · 全景** | 开场落在发布会上那一件具体事，按骨架把要点讲全 | 这场发了什么 |
| **B · 落地** | 开场偏「谁能用 / 怎么接」，门槛与场景多写一点 | 跟我有什么关系 |

用户说「只要一版 / 短帖 / 只要 A」→ 按口令裁。改某一版时，另一版事实不得漂移。

### 帖子结构（每变体内部）

```
开场：原文里那一件具体的事（读后口吻，不说「原文」）
→ 要点讲清（3～5；跟提纲，但不报目录）
→ 关键门槛 / 边界（有则写）
→ 怎么用 / 场景（归纳，不贴长代码）
→ 一句判断（可选，有代价；整帖最多一个「在我看来」）
→ 原链
```

**短线程**：按大节拆；第 1 条仍是完整主线；每条单独可读。两变体默认仍是两条「一条发完」的帖，不是两组线程。

**禁止**：大家以为…其实…；欢呼体；编个人评测；把「最强/首次」写成已测结论；结尾「提醒我们/值得关注」；互动乞讨；正文里的原文目录痕迹。

## 交付（正文优先，方便复制）

先给两个可复制正文，再附一份共用备注：

```markdown
## 变体 A · 全景

（全文）

约 N 字

## 变体 B · 落地

（全文）

约 N 字

## 备注
- 主线：…
- 两版差异：A …｜B …
- 提纲覆盖：…；略写：…
- 锚点：已核对 …｜说法 …｜判断 …｜未写入 …
- 来源：… + 原链
```

用户选定一版后，只在该版上改长短/语气/拆线程；**补全优先于再砍**。

## 交稿前自检

- [ ] 主线能指回 Title/开篇/H2
- [ ] 锚点分栏过了；无法确认未进正文；两版数字一致
- [ ] 开场是一件具体事；正文无「标题/原文小节」类痕迹
- [ ] 通顺门禁四条
- [ ] unslop 短帖档 + voice-profile
- [ ] 默认 2 变体（无 C）；文末有原链（模式 A）
