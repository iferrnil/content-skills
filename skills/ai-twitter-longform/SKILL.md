# 根据链接或 brief 写推特长文（含封面）

产出 X **长文/文章** + **贴合正文的封面**。主题偏 AI/科技。

吸收：`wechat-author-ai` 叙事/语气样本（无公众号动图脚本）；[sepia](https://github.com/Nanako0129/sepia) 节奏裁剪（`sepia-zh-longform`）。

「发条推」→ `ai-twitter-post`。「推特长文 / X Article / 要封面」→ 本 skill。

## 校准三条

1. 中间带  2. 一篇 **3～5 个要点**（例子通常 **1～2 个写透**）  3. 留一处平淡

## 人设（交稿前对照 voice-profile）

前开发者转 AI 自媒体：把事讲清楚，给中文读者**可带走的判断**。偏 **产品/技术预期**（谁受影响、该改什么预期），行业宏大叙事点到为止。半口语，像跟同行聊，不是社论。

---

## 动笔前三行（不过这三行禁止写正文）

必须先写出并在备注里保留：

1. **主线**（一句话，来自 Title+开篇，不是 H2 目录）
2. **读者带走**（给谁看 + 看完该改哪一个预期；答不出就换主线）
3. **选角**：单线深挖（评论/epilogue/邮件史默认）｜全景 3～5 点（发布通稿）｜机制+边界（教程/工程博文）

「同事问你这篇在说啥」——只能用第 2 行回答。答成「介绍了好多撤回」→ 重定主线。

---

## 英文原文保真（命中整篇重写）

工程博文 / 英文技术文常见翻车：**不是数字全错，而是压缩成口号，机制链条断了，读感像脱原文。**

1. **先机制后判断**：成文顺序是「讲清因果 → 再至多一句读者带走」；禁止先定金句标题/「组织成本」类观感，再倒填事实。
2. **术语首次落地**：专名保留英文或「中文（English）」；易混词必须消歧（如 Cosmos DB **container** ≠ Docker 容器：写「Cosmos 容器（吞吐与分区单位）」）。
3. **因果链不可砍腰**：若原文有 A→B→C（如存储涨→物理分区拆→总 RU 不变→每片配额变薄），中文必须保留完整链；只留口号句 → 重写该段。
4. **交稿前对照**：备注里列「段落 ↔ 英文哪一节」；找不到对应的段落删或改。数字、上限、官方自称不得改写。
5. **标题要对题**：读者只看标题应猜到产品/机制实体；禁脱原文重心的金句标题（如原文讲多租户绕圈，标题却只剩「组织付账」）。

坏味道加一行：

| 坏味道 | 表现 |
| --- | --- |
| 英源口号化 | 机制链被压成金句；术语没消歧；段落对不上英文节 |

---

## 两次翻车对应的硬禁（命中整篇重写）

| 坏味道 | 表现 |
| --- | --- |
| 来源缩写 | 小节顺序 ≈ 来源 H2；或把来源论点整段翻译一遍 |
| 年表/清单 | 日期撤回/发布列表 >3 条连堆 |
| 人名点卯 | 连续点名 >3；读者只记住名字记不住机制 |
| 替作者反省 | 复述「我系列文写错了/我认账」 |
| 议论文腔 | 「两股力」「短线/长线」「这意味着什么」「开源正在进入新稳态」当骨架 |
| 先堆事实后升华 | 连续 ≥3 句只有专名/数字，没有人话预期 |
| 无人可带走 | 删掉宏大结论后，不剩对开发者/使用者的具体预期变化 |
| 英源口号化 | 见上节 |

禁词（对照稿）：文里/文中/原文写/稿子里/通稿里/按原文小节/标题拎成主打。  
口径：他们说、官方公布、邮件里称、我看下来、我更在意。

正反例见 [`references/style-samples.md`](references/style-samples.md)。

## 怎么写（可执行）

### 顺序（反转常见错误）

1. 先写「读者带走」那句人话（幕后；**工程英源**：这句只能从机制链推出来，不能先于机制发明）。
2. 再挂 **1～2 个**具体例子把机制说清（事实 → 立刻人话）。第三个例子默认删。
3. 行业/AI-in-OSS 类引申 **最多一小段**，服务第 1 句，不另开社论。
4. 收束：≤1 句「在我看来」，有代价（还缺什么证据 / 解决了 A 没碰到 B）。

### 形态

- **默认少小标题**：连续散文为主；小标题 ≤2 且必须是实在信息（禁口号）。更接近「解说」，不是章节报告。
- 字数：**800～1400** 优先写透；宁短勿胀。英源机制文可偏长（靠近 1200～1400），**禁止为「爽」而砍因果**。
- 开场：一件具体的事（动作/数字/改动）。拿掉专名还能套上一篇 → 重写开场。

### 步骤（有链接）

1. Jina（`fetch-jina.md`）。失败则停。
2. 事实分栏（`stance.md`）——分栏是幕后清单，**不是正文大纲**。
3. 写「动笔前三行」。
4. 按上面「怎么写」成文 → 坏味道表（含英源口号化）→ style-samples → voice-profile → unslop A+B → sepia 节奏。
5. **英源**：备注写段落↔英文节对照；漏链则改。
6. 封面（`cover.md`）：贴合主线；5:2 / 1600×640。

无链接：先选题卡片；无出处不硬写新闻事实。

### 封面

先定稿再画；主文案=标题压缩或主线实体；禁止与正文脱节的装饰图。

## 交付

1. 标题 + 2 备选  
2. 正文  
3. 5:2 封面  
4. 备注：**动笔前三行**、略写了什么、封面是否已裁、来源；英源另加 **段落↔英文节**

## 交稿前自检

- [ ] 动笔前三行齐全；「同事一句话」测得过
- [ ] 坏味道表全未命中（含英源口号化）
- [ ] 例子 ≤2 写透；连续点名 ≤3
- [ ] 每段有事实→人话；无议论文骨架；关键因果链完整
- [ ] 小标题 ≤2 或无
- [ ] 英源：段落可指回英文节；术语已消歧
- [ ] unslop A+B + sepia；封面 5:2 贴合
